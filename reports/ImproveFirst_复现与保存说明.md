# ImproveFirst 分支保存说明

本分支保存2026年11月5日的单种子机制探索代码与实验成果。提交日期为2026年11月6日。原工作目录的用户报告和其他未提交文件未纳入本次提交。

当前普通验证集400对曲线、600个真实根；参数匹配采用一对一最大匹配。最佳验证 F1@0.01=0.8977072310405644，F1@0.035=0.9206349206349206，末步统一验证损失=0.19519732397197118。接受分数阈值0.98，参数去重半径0.025。全部为验证成绩，没有进行新独立测试。端点F1约0.0645，相切和近距离交点仍表现很差，不能宣称已找全所有交点。

模型外部输入是两组8×2控制点，固定三次、开放节点和全1权重。内部网格48×48、最多8个候选、5×5×3局部残差、10维附加几何特征；MLP为87→128→128→64→3，四步共享权重，单步限幅0.02。位移由MLP预测；没有Newton修正或按几何残差筛除输出。网格候选和硬去重仍为确定性操作。

`results/autoresearch_20261105/experiments/499729a3778b8a68/` 保存最佳训练过程、每5轮权重、选择出的第35轮权重、训练配置、验证指标与预测、当时源码。`c2873ed424b50971/` 是这次续训的起点。`6cf9fb8339190d8d/` 是最佳权重重新测量的历史结果。其余内容哈希目录保留其他成功或失败试验。

同一目录下 `controller_initial_archive/` 保存最初15轮有效实验及第16轮配置并发错误，`controller_latest/archive/` 保存续训命令超时且自动回退的记录，`controller_latest/` 顶层保存最佳权重重新测量后控制脚本确认完成的记录。不得把错误或超时记录改写为成功迭代。历史JSON中的绝对路径是原运行时的来源记录；实际文件已保存在本分支对应目录，不需创建原机器的绝对路径。

复核已有模型：在仓库根目录、安装NumPy的Python环境中运行：

```powershell
python -m code.evaluation.autoresearch_nurbs_protocol
python -m code.evaluation.autoresearch_nurbs_protocol --guard
```

当前默认配置只加载仓库中的最佳权重并重新评价，不启动新训练。输出写入被Git忽略的 `.tmp/autoresearch_nurbs/<内容哈希>/`。首次复核将重新计算普通验证集、特殊验证集和分数阈值，后续同内容使用缓存。环境版本见最佳结果的 `evaluation.json`。独立数据质量审计另需SciPy，可运行 `python -m code.experiments.autoresearch_nurbs.audit_data`。

如需重训最佳续训试验，先备份当前配置，将 `reuse_pretrained` 改为 `false`，把 `initial_weights` 改为 `results/autoresearch_20261105/experiments/c2873ed424b50971/weights.npz`，保持40轮、种子20261026及其余设置不变，然后运行同一评价命令。此时会重训40轮，再按固定验证规则选择检查点。控制脚本的历史结果目录为只读归档；要开启新自动试验，应使用技能脚本在干净分支初始化新的运行，不续写归档事件。

这份说明只完成Git归档与模型复核入口的整理，并不表示《实验改进指导》的全部要求已完成。尚缺自适应网格完整对照、特殊样本规范的最终落实、更新后的网络框架图、文献符号逐条核对和新独立测试。数据审计发现训练样本406在较密采样参考下根数不一致，尚未修正重训。
